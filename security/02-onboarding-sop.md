# SOP 02: First-Hour Onboarding Procedure

**Owner:** Customer Experience Lead  
**Author:** Manus AI  
**Status:** Ready for adaptation  
**Objective:** Ensure every new free-trial member experiences meaningful value within the first hour.

## Purpose

This SOP defines the onboarding process for a gaming membership service that promises fast setup and a 21-day trial. The first hour is the most important moment in the customer journey because it determines whether the user feels curiosity, confidence, or confusion.

The onboarding process should feel guided but not restrictive. A user should never wonder what to do next.

## First-Hour Experience Goal

> **First-hour goal:** The user should complete setup, understand the membership, access one meaningful feature or benefit, and know exactly what to explore next.

| Time Window | Experience Objective | Ideal User Feeling |
|---|---|---|
| 0–5 minutes | Welcome and orientation | "I understand what this is." |
| 5–15 minutes | Account, access, or setup confirmation | "This is easy to start." |
| 15–30 minutes | Guided first action | "I can use this right now." |
| 30–45 minutes | Discovery of premium value | "There is more here than I expected." |
| 45–60 minutes | Next-step recommendation | "I know what to do tomorrow." |

## Procedure

### 1. Welcome the Member With Confidence

The welcome message should repeat the core promise and reduce anxiety. It should not overload the user with every feature at once. The best welcome message is short, confident, and action-oriented.

**Recommended welcome copy:**

> **"Welcome in. Your 21-day access is active. Start with the quick setup, unlock your first experience, and see why members keep year-round access for $200."**

### 2. Create a Three-Step Setup Path

The onboarding path should include only the essential steps required to begin. Optional customization can come later. If the setup requires downloads, account linking, game selection, platform selection, or compatibility checks, those items should be placed in a visible sequence.

| Step | User Action | Team Standard |
|---|---|---|
| Step 1 | Confirm platform or game | Use plain language and avoid technical assumptions |
| Step 2 | Complete access or install requirement | Provide screenshots, short instructions, or a guided checklist |
| Step 3 | Launch first benefit | Direct the user to a clear first win |

### 3. Deliver a First Win

A first win is the moment when the user sees that the membership is useful. The first win should be specific, repeatable, and easy to complete.

Examples of first-win moments include a curated setup guide, a mod pack recommendation, a performance optimization checklist, early access to a resource, a member-only configuration, or a guided support interaction. The exact first win depends on the service, but the standard is always the same: the user should feel progress.

### 4. Prevent Confusion Before It Happens

The onboarding flow should include a short "If you get stuck" section. This section should appear before the user needs it, not after frustration begins.

| Confusion Point | Preventive Fix |
|---|---|
| User does not know where to start | Show a single recommended starting path |
| User is unsure about compatibility | Provide a platform/game compatibility note |
| User worries about trial billing | Display trial end date and billing explanation clearly |
| User cannot access a feature | Provide immediate support path and fallback instructions |

### 5. End the First Hour With a Next Step

The final onboarding screen or message should not simply say "you are done." It should guide the user into the next value moment.

**Recommended next-step copy:**

> **"You are set up. For the best experience, complete your first session today, return tomorrow for the recommended upgrade path, and check your trial dashboard before day 7."**

## Quality Control

The onboarding process should be tested with someone who has not seen the service before. If that person needs repeated explanation, the SOP has not been met.

| Metric | Target |
|---|---|
| Time to understand the offer | Under 2 minutes |
| Time to complete essential setup | Under 60 minutes |
| Number of required choices before first value | As few as possible |
| Support visibility | Always visible during setup |
| Trial status visibility | Clear from the first session |
